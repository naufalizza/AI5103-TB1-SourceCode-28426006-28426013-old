## Installation

Requirements: R ≥ 4.3 with `Rcpp`, Python ≥ 3.11, a C++ compiler.

```bash
# R side (macOS: brew install r)
Rscript -e 'install.packages("Rcpp", repos="https://cloud.r-project.org")'
its_mcttrp/src/build.sh                 # compiles itsmcttrp.so

# Python side
python3 -m venv .venv
source .venv/bin/activate
pip install -r ga_pso/requirements.txt
```

## Reproduce everything

```bash
python run_its_batch.py && python ga_pso/run_experiments.py && python ga_pso/run_experiments.py --sensitivity && python ga_pso/compare.py
```

1. `run_its_batch.py` runs the original ITS (100 iterations, as in the paper) on every instance and seed.
2. `ga_pso/run_experiments.py` gives GA-OX, GA-PMX and PSO a wall-clock limit equal to the mean ITS time on each instance.
3. `--sensitivity` varies the GA mutation rate and the PSO final inertia on `CHAO_MCTTRP_01`.
4. `ga_pso/compare.py` writes `results/summary.csv`, `reproduction.csv`, `stats.csv`, `sensitivity.csv`, `all_runs.csv`, the figures in `report/figures/` and the LaTeX tables in `report/tables/`.

All scripts skip runs that already have a result file, so they can be interrupted and restarted. Seeds and parameters live in `config.json`.

Single runs:

```bash
cd its_mcttrp && Rscript run_its.R instances/P1.csv 2 1 100 600 1 /tmp/p1.json
cd its_mcttrp && Rscript reproducibility/Real_problems_MCTTRP_repo.R   # original script
```

## Tests

```bash
cd ga_pso && ../.venv/bin/pytest -q
```

The tests check the instance parser, the feasibility checker against the optimal solution printed in Section 5.1 of the paper (207 km), the decoder, the ITS output parser, the GA/PSO operators and the experiment runner.

## Modelling decisions shared by all algorithms

The paper's text and its MILP disagree in two places. The validator (`ga_pso/mcttrp/solution.py`) and the decoder follow the rules that match the original code and the reference values:

- **Fleet:** trailers used ≤ m_L and trucks used ≤ m_T. The MILP's constraint (10) would allow at most m_T − m_L pure-truck routes, but the paper's own Table 4 breaks it (instance 2: 8 trucks, 4 trailers, 4 PTRs) and so does the original code.
- **Trailer parking:** only at a vehicle customer on the main tour, never at the depot. Constraint (10) forbids depot-rooted routes for trucks with a trailer, the Gurobi optima use that model, and the original ITS never parks at the depot. An earlier run that allowed depot parking produced costs below the proven optima (e.g. 199 vs 222 on P6); those results are kept in `results/archive_depot_parking/` for reference only.

## Fixes applied to the original code

| File | Problem | Fix |
| --- | --- | --- |
| `R/MCTTRP_main.R` | Loaded `src/itsmcttrp.dll` (Windows only) | Loads `itsmcttrp.so`/`.dll` for the current OS; `src/build.sh` compiles it |
| `load_its.R` (new) | `&&`/`||` on vectors (e.g. `capacidad.vehiculo`) is an error since R 4.3; the code relied on R 4.0.2 using the first element | Restores the R 4.0 behaviour for these two operators |
| `src/movlist.cpp` | `calc_penalty_route_MCTTRP()` read demand column `j+1` for `j = 0..nf-1`: skipped product 1 and read past the matrix (out-of-bounds) | Uses column `j` |
| `reproducibility/*.R` | Scripts did not load the solver | `source("load_its.R")` added |
| `reproducibility/Real_problems_MCTTRP_repo.R` | Final loop used undefined `result` | Uses `real_problem` |
| `R/MCTTRP_opt_method.R` | No convergence data | Records best feasible cost per iteration (`.its_trace`) |

Known differences from the paper: `reproducibility/CHAO_MCTTRP_repo.R` uses 2 iterations for instances 13–21 while the paper reports 100; this project only uses instances 1–6 with 100 iterations.
